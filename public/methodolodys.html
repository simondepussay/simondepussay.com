Methodolodys

スイスの特別支援教育の先生 Martine Jiménez さんが10年かけて作った、Dys（ディスレクシアなど）の子ども向け無料教材サイトです。WordPressで動いていたこのサイトを、教材を一つも失わずに、速くて安全な静的サイトへ作り直しました。
A free learning-resources site for children with dyslexia and other « dys » disorders, built over 10 years by Martine Jiménez, a special-needs teacher in Switzerland. I rebuilt it from WordPress into a fast, secure static site, without losing a single resource.

1. なぜ作り直したか Why rebuild it

見た目は動いていても、中身は古くなっていました。毎日先生や保護者が使うサイトなので、壊れる前に作り直すことにしました。
The site still worked, but it was ageing underneath. Teachers and parents use it every day, so it was worth rebuilding before something broke.

  • 技術的負債 / Technical debt — サポートが終わったPHPとMySQL、7つのプラグイン（もう開発されていないものも）、更新を待つものが複数。WordPress本体、テーマ、プラグインを常に更新し続ける必要がありました。 Technical debt — PHP and MySQL versions past end of life, 7 plugins (some no longer maintained) and several updates pending: WordPress, the theme and every plugin needed constant upkeep.
  • セキュリティ / Security — バックアップのセキュリティログには、管理画面への数百回のログイン失敗（総当たり攻撃）が残っていました。静的サイトには、攻撃されるログイン画面もデータベースもPHPもありません。 Security — the security logs in the backup showed hundreds of failed logins on the admin page (brute force). A static site has no login page, no database and no PHP to attack.
  • 速さ / Speed — 旧サイトはページごとに1.1〜1.5秒かけてPHPでHTMLを作っていました（キャッシュ込み）。新サイトは完成したファイルを返すだけなので約7ミリ秒。HTMLも33 KBから1〜3 KBに。 Speed — the old server spent 1.1–1.5 s building each page in PHP, even with its cache. The new one just returns ready files: about 7 ms. Page HTML went from 33 KB to 1–3 KB.
  • 使いやすさ / Easier to use — 1つの長いページに数百のPDFが並んでいたのを、テーマごとのページ、検索、プレビュー画像、Dysの人のための読みやすさ設定に分けました。 Easier to use — instead of long pages listing hundreds of PDFs: one page per topic, a search, preview images and reading settings for dyslexic readers.

数値：東京からcurlで計測（5回の中央値、接続時間を除く）、2026年10月。旧サイトはまだ公開中なので、セキュリティの詳細は載せていません。
Figures: measured from Tokyo with curl (median of 5, connection time removed), October 2026. Security details are left out while the old site is still online.

2. 全体の構成 Architecture

ページ（16 MB）とダウンロード用のファイル（5.3 GB）を分けました。ページはAzure Static Web Apps、ファイルはAzure Blob Storage。どちらも管理するサーバーはありません。
Pages (16 MB) and downloadable files (5.3 GB) are kept apart: pages on Azure Static Web Apps, files on Azure Blob Storage. No server to manage on either side.

3. 5.3 GBのファイルをAzureへ 5.3 GB of files on Azure

このサイトの中心は、10年分の教材ファイルです。ページの中に入れると、Static Web Apps無料プランの上限（250 MB）の20倍以上になります。そこでファイルだけをBlob Storageに置き、ページからは直接リンクしています。
The heart of the site is ten years of teaching files. Inside the pages they would be over 20 times the Static Web Apps free-plan limit (250 MB), so the files live on Blob Storage and the pages link to them directly.

何が入っている？ What is stored?

PDF、PowerPoint、Word、動画・音声の1 909ファイル。そのうち1 097枚は「視覚意味辞書」（単語カードとその説明）です。全教材のタイトル・場所・種類・サイズ・日付は1つのJSON（1 920件）にまとめ、ページと検索はこのJSONから作ります。
1,909 PDF, PowerPoint, Word, video and audio files, including 1,097 cards of a visual-semantic dictionary (a word card and its explanation for each word). One JSON file (1,920 entries) describes every resource: title, page, section, type, size and date. Pages and search are built from it.

どうやって確認した？ How was it checked?

アップロード後、ローカルとAzureの全ファイルを名前とサイズで比べました（差分0）。次に、公開されたサイトの1 909個のダウンロードリンクを全部、実際にリクエストして確認しました（エラー0）。アクセント付きのファイル名（« trésor.pdf »など）も正しく開きます。
After the upload I compared every file by name and size between my Mac and Azure (0 differences), then requested each of the 1,909 download links of the published site (0 errors). File names with accents, such as « trésor.pdf », open correctly.

コストは？ Cost?

ページはStatic Web Appsの無料プラン。ファイルの保存は月に数十円程度。ダウンロードの転送量は、無料枠（月100 GB）を超えた分だけ課金されます。
Pages run on the Static Web Apps free plan. Storing the files costs a few cents a month; download traffic is only charged past the free 100 GB a month.

4. 失わない移行 A lossless migration

  1. 読む Read 12 GBのバックアップから必要な7.2 GBだけを取り出し、MySQLダンプとページビルダーDiviのショートコードを順番どおりに解析。 Take the 7.2 GB that matter out of a 12 GB backup, then parse the MySQL dump and the Divi page-builder shortcodes in page order.
  2. 直す Repair 文字化けしたファイル名、2つのURLがくっついたリンク、閉じていないブロック、「こちらをクリック」だけのタイトルを自動で修正。 Fix mojibake file names, links with two glued URLs, unclosed blocks and titles that only said « click here ».
  3. 補う Complete 画像のない144の教材には、ファイルの1ページ目からプレビューを作成。旧トップページにしかなかった2つの教材も見つけて移しました。 Generate a preview from the first page of the 144 resources without an image, and recover 2 resources that only existed on the old homepage.
  4. 確かめる Verify 全ページのリンク・画像3 000件以上、71のリダイレクト、1 909のダウンロードをスクリプトで確認してから公開。 Check 3,000+ links and images, 71 redirects and 1,909 downloads by script before publishing.

6. 設計で考えたこと Design decisions

  • フレームワークなし — 依頼者が将来自分で直せるように、素のHTML・CSS・JavaScriptだけ。 No framework — plain HTML, CSS and JavaScript, so the site stays easy to maintain later.
  • Dysの人のための読みやすさ — OpenDyslexicフォント、文字サイズ、行間をワンクリックで変更。フォントは選んだ人にだけ読み込みます。 Built for dyslexic readers — one-click OpenDyslexic font, text size and spacing; the font is only downloaded by those who choose it.
  • 古いリンクを守る — 10年分の共有リンクやブックマークが切れないよう、旧URLを新しいページへ301リダイレクト。古いPDFへの直接リンクも転送します。 Keep old links alive — ten years of shared links and bookmarks keep working: old URLs are 301-redirected, old direct PDF links forwarded.
  • テスト中は検索に出さない — 同じ内容のサイトが2つ検索に出ないよう、テスト版には noindex を付けています。 Hidden from search engines while in test — the test version sends noindex, so search engines never see two copies of the same site.

7. まだやっていないこと Not done yet

依頼者の確認を待っているテスト版です。まだのこと：methodolodys.ch のドメインの切り替え、利用者に近いヨーロッパのリージョンへの移動（いまは学生用サブスクリプションの制限で東アジア）、編集を簡単にするための更新手順の整備。
This is a test version waiting for the owner's review. Not in place yet: switching the methodolodys.ch domain, moving to a European region closer to its users (East Asia for now, because of the student subscription's region policy), and a simpler update workflow for the content.

8. 作り方と学んだこと How it was built, what I learned

Claude Code（AIのコーディングエージェント）と一緒に作りました。移行の方針、ページの構成、何を残して何を直すか、公開の判断は私が決め、毎回ブラウザで確認しました。大きな移行では、作ることより「何も失っていない」と証明することのほうが大事だと学びました。
Built with Claude Code, an AI coding agent. I decided the migration plan, the page structure, what to keep and what to fix, checked every change in the browser and made the publishing decisions. On a large migration, proving that nothing was lost matters more than building fast.
